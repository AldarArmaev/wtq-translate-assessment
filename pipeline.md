# Pipeline оценки перевода WikiTableQuestions

Редактируемая схема находится в [pipeline.drawio](pipeline.drawio). Открыть её можно в draw.io / diagrams.net через «Файл → Открыть из → Устройство».

## Назначение

Проект оценивает готовый перевод вопросов и таблиц с английского на русский. Python выполняет формальные проверки, LLM проверяет смысл, а Python агрегирует решения. Перевод и обратный перевод выполняются внешним пайплайном до этого эксперимента. Эталонные ответы `targetValue` не используются: точность решения вопросов не измеряется.

## Последовательность

1. **Настройка.** Загрузить CLI и `.env`: пути, провайдер и модель судьи, температуру, seed, размер выборки, лимит ячеек и размер пакета. Проверить соответствие версии рубрики хешу промптов в `rubric_lock.json`. По умолчанию: 200 примеров, seed 42, лимит 150 ячеек, пакет 40 ячеек, температура 0.
2. **Выбор примеров.** Прочитать русский `training.tsv`. Выбрать ID воспроизводимо по seed либо взять список `--ids-file`. Сохранить ID в `sample_ids.json`. Пример — один вопрос с таблицей и trace, а не отдельная ячейка. Одна исходная таблица может встречаться в разных примерах.
3. **Продолжение запуска.** При `--resume` переиспользовать выбранные записи без ошибок разделов после проверки хеша рубрики. Совпадение остальных условий, включая модель и входные данные, нужно обеспечить отдельно. Некоторые локальные пропуски LLM могут не отражаться в ошибках раздела.
4. **Загрузка примера.** Английский вопрос и путь исходной таблицы взять из trace, русский вопрос и путь русской таблицы — из датасета. Прочитать таблицы, нормализовать пробелы и некоторые escape-последовательности. Скопировать готовую диагностику перевода из trace.
5. **Проверка структуры.** Сравнить количество строк данных, количество столбцов заголовка и длины соответствующих строк. Проверка охватывает всю таблицу, но одинаковые размеры не гарантируют правильный порядок содержимого.
6. **Подготовка пар и проверки правилами.** Сопоставить исходные и русские ячейки по координатам. Классифицировать исходный текст как пустой, URL/email, числовой, символы, дату, код или текст. Проверить неизменяемые значения строго и с допуском оформления; оценить пропущенный перевод и заполнение исходно пустой ячейки. Полностью пустые пары исключить. Подготовка всех пар не означает отправку всех ячеек судье.
7. **Отбор ячеек.** Если подготовленных ячеек больше лимита, сохранить заголовки и все ячейки, связанные с упоминаниями, включая координаты-кандидаты. Остальные места до лимита заполнить воспроизводимым случайным отбором. Обязательных ячеек может быть больше лимита — тогда они сохраняются все. `--max-cells 0` отключает ограничение. В итоговые оценки содержания входят выбранные ячейки.
8. **Судья текстовых ячеек.** Среди отобранных взять непустые текстовые пары, требующие LLM. В пределах примера убрать повторы по тройке «английский заголовок + исходный текст + русский перевод». Передать уникальные тройки пакетами до 40 элементов по умолчанию вместе с доменом. Полная таблица и вопрос не передаются. Получить правильность перевода, сохранение информации и отсутствие добавлений. Распространить решения на повторяющиеся выбранные ячейки.
9. **Упоминания.** Сравнить `original_masks` и `forward_masks` из trace: это маркеры до и после прямого перевода, а не русский и английский текст. Для каждого упоминания взять явную координату или первую координату-кандидат; прочитать английский и русский элементы, собрать русские варианты того же исходного текста среди кандидатов. Простые случаи проверить правилами; остальные передать LLM пакетами до 25 упоминаний с обоими вопросами и данными элементов. Получить русский фрагмент, правильность цепочки и смысловую согласованность. Применить правила для изменённых неизменяемых значений, проверить наличие фрагмента, вычислить поверхностное совпадение и наличие текста ячейки в вопросе.
10. **Судья вопроса.** Передать английский вопрос, русский вопрос и домен в отдельный вызов, без таблицы и эталонного ответа. Получить сохранение смысла, правильность ключевых элементов, сохранение логики, естественность русского и критический флаг с замечаниями.
11. **Итоговый критический флаг.** Объединить решение судьи вопроса, проблемы упоминаний и изменения связанных неизменяемых значений. Любой источник равен 1 → итог 1; все три равны 0 → итог 0; иначе `null`. Отсутствие оценки отдельного упоминания не всегда делает источник упоминаний неопределённым, поэтому нужно отдельно проверять покрытие.
12. **Сохранение и агрегация.** Записать индивидуальные результаты в `evaluation.jsonl`, ошибки загрузки и разделов — в `errors.jsonl`. После обработки отсортировать записи по ID. Вычислить общие доли, интервалы Уилсона 95%, среднее долей по примерам и статистику диагностики. Сохранить `summary.json` и `report.txt`.
13. **Ручная валидация.** Отдельно от автоматического кода проверить ошибки выполнения, покрытие, критические примеры и случайную часть примеров без критического флага. Разделить ошибки перевода, привязки и судьи.

## Лимит и пакеты — разные параметры

Условный пример: **500 подготовленных ячеек → 150 выбранных → 70 непустых текстовых пар для LLM → 55 уникальных троек → два запроса: 40 + 15**. Остальные выбранные ячейки проверяются правилами. Невыбранные ячейки не входят в индивидуальную оценку содержания, хотя структура таблицы проверяется целиком.

## Общий механизм обращений к судье

Каждая задача сначала ищет ответ в кэше по провайдеру, модели, температуре, рубрике и сообщениям. При отсутствии ответа выполняется запрос и проверка JSON, ID и бинарных полей. Невалидные ответы и некоторые временные сбои вызывают повторные попытки. Устойчиво неуспешные пакеты ячеек/упоминаний делятся пополам до отдельного элемента; неуспешный элемент остаётся без смысловой оценки. Температура 0 не гарантирует абсолютной воспроизводимости сервиса.

Примеры обрабатываются параллельно, но внутри примера разделы идут последовательно: таблица → упоминания → вопрос → итоговый флаг. Диагностика BERTScore/cosine из trace не участвует в критическом флаге.

## Выходы и ограничения

| Файл | Содержание |
|---|---|
| `sample_ids.json` | Состав выборки |
| `evaluation.jsonl` | Оценки каждого сформированного примера, замечания и ошибки разделов |
| `errors.jsonl` | Технические ошибки оценщика, а не список ошибок перевода |
| `summary.json` | Агрегаты, знаменатели, интервалы и метаданные |
| `report.txt` | Читаемая сводка |
| `cache/` | Ответы судьи |

`null` исключается из знаменателей; отсутствие результата не равно успеху. Общая доля по ячейкам и среднее по примерам имеют разные веса. Интервалы Уилсона не учитывают ошибки судьи и зависимость ячеек внутри таблиц. Единого общего балла нет.

`--no-llm` выполняет только проверки правил. `--aggregate-only` печатает пересчитанную сводку существующего JSONL без новых обращений к судье; в текущем коде не перезаписывает файлы сводки.
