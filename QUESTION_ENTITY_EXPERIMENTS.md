# Эксперименты с сущностями вопросов

Ветка `codex/question-entity-experiments` добавляет отдельный сценарий `question_entity_experiments.py`.

Он выполняет ровно два опыта на одной выборке:

1. `forward`: исходный английский вопрос из trace против русского вопроса из датасета.
2. `back`: тот же английский оригинал против `quality.back_translated_question` из trace.

Таблицы не загружаются. Оценка ячеек, упоминаний и общий судья вопроса не вызываются. Проверяются только сущности через общую функцию `entities.evaluate(..., cells=[], target_lang=...)`. Оба варианта используют одни и те же 18 типов и порог 0,5. Для forward кандидат обрабатывается как RU, для back — как EN. Отсутствие обратного перевода приводит к ошибке до запуска моделей и расходов на API: русский вопрос не используется как запасной вариант.

Системный промпт проверки сущностей теперь допускает русский перевод и английский обратный перевод; версия рубрики повышена до v2.1. Алгоритм сопоставления и обработки отсутствующих детекций сохранён, чтобы сравнивать именно варианты входа.

Данные каждого опыта, время, отдельный кэш и все попытки API сохраняются в собственных папках. `api_attempts.jsonl` не содержит ключей или заголовков авторизации. Статус `response_received` означает получение ответа API; он сам по себе не гарантирует прохождение последующей JSON-валидации. Каждая повторная попытка имеет свою запись.

Запуск:

```powershell
python question_entity_experiments.py --dataset-dir wtq-ru-full/runs/training-fe81e969e126/dataset --trace-dir wtq-ru-full/runs/training-fe81e969e126/traces/training --out-dir output/question-entities-new --sample-size 3 --seed 42
```

Модель по умолчанию: `deepseek/deepseek-v4-flash-0731`; провайдер OpenAI-compatible. Настроить `OPENAI_API_KEY` и `OPENAI_BASE_URL`. Для отдельного хранилища NLP-моделей доступен `--entity-model-dir`.

Результаты проведённых опытов: [RESULTS.md](output/question-entities-forward-vs-back-3/RESULTS.md). Старый полный pipeline `evaluate.py` сохранён.
