# Методика v2: сущности и упоминания

Ветка: `codex/entity-and-mention-evaluation`. Оценщик работает с готовым переводом; переводчик в этот репозиторий не входит.

## Pipeline

1. Загрузка датасета, trace и исходной/русской таблиц.
2. Проверка структуры и пар ячеек по координатам. Лимит ячеек по умолчанию отключён (`--max-cells 0`).
3. Оценка текстовых ячеек прежней рубрикой: верность, полнота, отсутствие добавлений. Передача пакетами до 40 уникальных троек.
4. Проверка масок упоминаний. Правильность упоминаний теперь оценивается **только по `question_text` → `translated_text` из trace**. Таблицы, координаты, обратный перевод и соседние упоминания не передаются судье и не переопределяют эту оценку. Отсутствующее поле `translated_text` означает неизвестную оценку, пустая строка — ошибку. Старые метрики согласованности с ячейкой из текстового отчёта v2 убраны.
5. Отдельный этап сущностей из вопроса и всех выбранных ячеек. Stanza сегментирует текст, многоязычная NER-модель `urchade/gliner_multi-v2.1` независимо извлекает сущности из EN и RU. Одинаковые тексты внутри примера анализируются однократно. Длинные предложения разбиваются на перекрывающиеся окна, результаты объединяются по символьным позициям.
6. LLM сопоставляет сущности в пределах пары вопроса или ячейки, проверяет сохранение их идентичности/значения. Типы модели-судье не передаются. Валидация требует взаимно однозначного соответствия ID; отсутствующие соответствия и лишние детекции сохраняются явно.
7. Python сравнивает типы сопоставленных сущностей и отдельно сравнивает количество детекций каждого типа в паре. Это сравнение типов программное, но соответствие сущностей опирается на LLM. Совпадение распределения типов само по себе не доказывает сохранение сущностей.
8. Оценка вопроса и прежний итоговый критический флаг; новая оценка сущностей сохраняется отдельно и автоматически в критический флаг не включается.
9. Агрегация, отчёты и время каждого примера.

## Расширенный набор

18 меток GLiNER: person, organization, location, geopolitical entity, nationality, facility, product, event, work of art, law, language, date, time, money, percentage, quantity, ordinal, cardinal. Порог 0,5. Одинаковая модель и набор меток применяются к обоим языкам; это позволяет избежать прямого сравнения несовместимых инвентарей стандартных Stanza NER EN/RU.

Stanza используется для токенизации/сегментации, а не как модель, предсказывающая эти 18 типов. Извлечение всех существующих сущностей не гарантируется: NER может пропустить или неверно классифицировать сущность; длина сущности также ограничена архитектурой GLiNER. Числа и даты относятся к расширенному набору, хотя не все из них — имена собственные.

## Метрики сущностей

- `type_preservation`: доля исходных сущностей с найденным соответствием и тем же NER-типом; отсутствующее соответствие даёт 0.
- `meaning_preservation`: доля исходных сущностей, признанных LLM сохранёнными по смыслу.
- `type_counts_equal`: доля пар с одинаковыми количествами детекций каждого типа; включает пары без сущностей с обеих сторон, поэтому читать вместе со счётчиками.
- `n_source_entities`, `n_translation_entities`: число детекций с учётом повторов в разных ячейках.
- `n_unmatched_target_entities`: число несопоставленных русских детекций. Это не доказанные добавления переводчика: причиной может быть пропуск английского NER.
- `n_failed_pairs`: пары с сущностями без валидного решения LLM. Их оценки не входят в знаменатель.

Рубрика v2.0 и новый хеш отделяют результаты от v1.0. Отсутствующие оценки не заменяются успешными. Для надёжного вывода нужна ручная валидация NER и соответствий.

## Время

Для сопоставимого замера используются один работник, те же ID и отдельная изначально пустая папка кэша. `elapsed_seconds` записи — время загрузки и оценки примера, включая NLP и запросы API; `entity_seconds` — время этапа сущностей. `meta.mean_example_seconds` — среднее этих длительностей. `meta.entity_setup_seconds` — инициализация/скачивание моделей, отдельно от оценки примеров. `meta.elapsed_seconds` — обработка запуска после инициализации моделей. При повторном запуске с кэшем время уже не соответствует холодному API-замеру.

Первый запуск скачивает NLP-модели; файлы хранятся в `.models`. Ошибка загрузки не должна подменяться оценкой без NER. На данной машине для HTTPS потребовалось системное хранилище сертификатов через `truststore`, без отключения проверки TLS.
